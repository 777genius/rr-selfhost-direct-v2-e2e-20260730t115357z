This is a finite synthetic transport experiment against the actual pinned Go engine. It does not run real agents, OAuth identities, financial reviews, or live providers. Only this directory is owned. Existing broker code is imported read-only; the adapter, original fixture, runtime-lab and engine accounting are unchanged.

The worker cannot execute Docker, inspect auth homes, or obtain credentials. The coordinator reviews these files, builds/deploys an isolated engine, supplies telemetry and executes the commands below. No operator response is required by a running batch.

1. Use a unique disposable project/network and new empty private/evidence directories. `compose.example.yaml` is a coordinator template, not an executed deployment. Resolve its paths from the repository root with `--project-directory .`. Use only immutable digests for all four image variables. Set up synthetic PostgreSQL and engine env files using the existing coordinator bootstrap; standard mode, no production data. The engine's only network is internal, with PostgreSQL, Redis and `http://mock:8099`. Publish no ports. Do not attach other provider networks. No Docker socket or auth-home mounts. The Node service runs UID 1000; privately provision directory ownership/modes accordingly. Keep evidence/telemetry free of tokens.
2. Write `/private/deployed.json` from actual inspection of the running container and verified build source. Include all fields in `config.example.json.deployment`, plus `inspected: true`, numeric `engine_pid`, and `clock: "linux-CLOCK_MONOTONIC"`. `instance` identifies this immutable deployment. `source_manifest_sha256` hashes build source, never a credential. For a patched image use `variant: "patched"`, the actual image digest and public patch hash; retain the parent source SHA. Never substitute the original image label. The scripts compare every supplied pin; trust in the coordinator's actual inspection is explicit, not independent image attestation.
3. Obtain a fresh synthetic deployment admin session outside this worker and put the generated bearer in `/private/admin-bearer`, mode 0600. In the isolated operator container run `node sub2api-regression-lab/init.mjs /private/deployed.json /private/admin-bearer`. It refuses an existing `/private/lab.json`, generates only synthetic sentinels/control authorization, and prints no credentials. Do not run it with production admin credentials. Start the mock after this initialization.
4. Run `node --test sub2api-regression-lab/lab.test.mjs` in the isolated Node24 container. These are protocol, receipt, socket-fixture and actual-broker contracts. They do not prove Go behavior. Then review `node sub2api-regression-lab/run.mjs --plan` and start the root telemetry collector before any load batch.
5. Run one explicit batch: `node sub2api-regression-lab/run.mjs --case cancel-responses-after-client`. The plan lists all 40 valid names. To execute an entire finite stage use `node sub2api-regression-lab/stages.mjs cancel` (also `uncertainty`, `memory`, `soak`). The supervisor runs distinct cases once, stops on ambiguity/unknown or duplicate effects, unexercised health, unsafe cleanup, or oversized load. Expected immediate-abort FAIL permits the next fresh cancellation case. Any nonzero exit retains its receipt; inspect effects before considering another planned experiment. A failed admission is not a retry request.
6. Consume `/evidence/<case>.json`. Only explicit PASS at that boundary counts. Missing engine telemetry leaves load `acceptance_status: "NOT RUN"` even if its protocol/effect gate passed. Retain all original FAIL/NOT RUN receipts. Admission files and private journals refuse ambiguous reruns; use a new reviewed project/config/evidence directory for a distinct corrected experiment. No automatic inference retry, redirects, model replacement or protocol conversion exists in these clients.
7. Cleanup runs for every recorded resource. On incomplete cleanup run `node sub2api-regression-lab/cleanup.mjs <case>` in the same project. It deletes only IDs recorded by this batch. An ambiguous create intention remains explicit; reconcile actual admin objects using that private intention before deleting them. No global account enumeration/deletion is performed by this worker. Coordinator then tears down only this disposable project and its private state.

Every case creates one fresh exclusive group/account, verifies actual bindings/no fallback, and makes a successful healthy request on that account before admission. Responses account creation may still launch a capability probe despite `upstream_billing_probe_enabled=false`; that flag controls billing probes. All such actual preparation requests/effects are separately counted. There is no attempt to clear another lane's cooldown. A scheduler denial without an upstream request cannot pass a fault oracle.

Cancellation has twelve cells: Responses/Messages × before output/after acknowledged output × client disconnect/actual broker revoke/actual broker expiry. The broker uses its real module with a synthetic verifier; this is not signed OIDC evidence. Its response-close event timestamps the observed cancellation boundary. A new request must be denied after broker revoke/expiry. The direct cancellation account has one slot, and a healthy control after deliberate drain checks post-release availability, not immediate capacity release.

Linux `process.hrtime.bigint()` supplies independent monotonic measurements in the same kernel CLOCK_MONOTONIC domain. The upstream separately records acceptance/effect, first write call, first successful transport-write callback, received client acknowledgement, release/reset, terminal-write callback and actual socket close. A write callback establishes local transport flush, never remote receipt. The client records a fully parsed native text-delta frame >4 KiB, cancellation call, client close and terminal receipt. Header receipt and small `response.created` events do not count as semantic acknowledgement. In after-frame cases the acknowledgement reaches mock control before cancellation/reset. HTTP flush alone is never proof of client commitment.

For cancellation the mock holds after acceptance/early frame for ten seconds and only an explicit control release completes it; a separate safety deadline destroys an abandoned socket. The immediate-abort oracle requires actual upstream close within 1.2 seconds, before release and without a terminal. Default Sub2's deliberate usage drain is expected to FAIL this oracle and is preserved. A post-release terminal cannot retrospectively become cancellation evidence. No promise of stopping remote provider spend is made.

Uncertainty has four placements per native protocol: accepted effect before semantic output, after acknowledged frame, after a real tool-call turn and accepted matching tool result, and pending transport reset before the mock's effect acceptance. All resets are explicit. The mock increments an actual synthetic effect counter independently of response bytes. Expected counts are one attempt/one effect in the first three placements, one attempt/zero effects in pending reset. Counts are rechecked at the final batch boundary, including engine attempts; duplicate attempts fail even when no additional effect was accepted. This is a finite observation through downstream termination/quiescence, not an indefinite retry guarantee.

Memory has eighteen batches: 8/32/64 MiB × concurrency 1/5/20 × both native protocols. The consumer discards streaming data, keeping at most one bounded frame. Each stream contains real UTF-8 text deltas, SSE comments, a roughly 960 KiB tool-argument frame and valid native terminal/output association. Large wire size comes from comments so a legitimate terminal is still under 1 MiB. This tests aggregate backpressure plus near-limit native frames; it does not cover a single 64 MiB semantic frame. No client RSS is used as engine evidence. Soak is exactly two batches of 250 requests, five concurrent, totaling 500. Nominal planned inference/preparation controls total 722 plus actual automatic create probes; all share the mock's 2,000-attempt cap. Every batch has an 85-second internal budget and a 90-second supervisor ceiling. Oversized load cancels consumers and destroys owned upstream sockets; effects/drain state are retained.

The root collector appends `/telemetry/<case>.ndjson`, one complete JSON line per 100 ms, from the actual Go PID/cgroup (never Node/client PID). Each line contains only:

```json
{"collector":"root-go-pid","batch_id":"memory-responses-8-1","instance":"owned-instance","engine_pid":123,"clock":"linux-CLOCK_MONOTONIC","mono_ms":1000,"phase":"baseline","peak_reset_ms":1000,"rss_bytes":104857600,"cgroup_current_bytes":110100480,"cgroup_peak_bytes":110100480,"cgroup_limit_bytes":805306368,"sockets":2,"goroutines":20}
```

Those numbers illustrate the schema, not engine measurements. Require an actual baseline within one second before the load boundary and an actual cgroup-peak reset for this batch. Continue samples without gaps >250 ms. `/evidence/<case>.start.json` and `.end.json` give monotonic boundaries and actual expected engine identity; inspect `--plan` to prepare the collector before admission. After `.end.json`, append measured `phase: "quiescent"` data within five seconds; the runner allows two seconds of ordinary quiescence collection. Missing/invalid identity, baseline, samples or return data produces NOT RUN. A failure observed with valid actual telemetry stops the batch without waiting for an operator.

Measured gates: peak RSS delta ≤128 MiB +16 MiB/stream; absolute RSS ≤512 MiB; quiescent RSS return within 32 MiB of baseline. Cgroup limit is 768 MiB; reaching it is FAIL. Socket/goroutine peaks and quiescent counts are recorded; no invented count bound is asserted. Idle pooled sockets are not classified as stuck inference; actual open upstream request records are counted separately. Root should collect through safety-stop/drain and retain the tail even if a batch fails early. Never include proc environment, command lines, provider contents or tokens in telemetry.

Each test's name and each planned receipt's `red` field state the observable regression that defeats its oracle. Receipt unit tests deliberately retain a default usage-drain FAIL, reject absent upstream effects and reject client/sparse telemetry. Only executing these scripts against the exact real engine can establish that engine's verdicts.
