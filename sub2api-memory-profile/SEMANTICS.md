`runtime/mstats.go:350-363` says ReadMemStats allocator statistics are current at the call and stops the world to read them. It does not run a collection. HeapAlloc/HeapObjects include allocations that have not yet been collected; they are **not current reachable live heap**. HeapInuse is occupied spans, with size class fragmentation. HeapIdle includes spans available for reuse; HeapReleased is the portion returned to the OS. These classes do not equal process RSS. NumGoroutine is an instantaneous total, including instrumentation goroutines, and is not an orphan-reader count. LastGC is Unix nanoseconds, while sample brackets use Linux CLOCK_MONOTONIC milliseconds; never subtract those clocks.

`runtime/pprof/pprof.go:125-143, 604-660` documents sampled heap data at completed collections and the no-collection exception. Lookup("heap").WriteTo(file, 0) calls writeHeapInternal and the runtime profiler bucket reader. Lookup("allocs") selects the same data with alloc_space as the default display. Neither method requests a fresh GC. `runtime/mprof.go:905-991` explicitly allows **up to two GC cycles of lag** and flushes active/future profiler buckets under locks. A ReadMemStats NumGC bracket does not identify the profiler's internal bucket epoch. The harness preserves pre/post counters separately for each profile kind and never invents that epoch. A profile with no later natural cycles cannot distinguish garbage from retained roots.

`runtime/pprof/protomem.go:15-85` emits four sample types and scales samples by their inclusion probability. Heap profile inuse_space/inuse_objects are weighted estimates, not exact allocation totals. Allocs is cumulative sampled allocation evidence, not a leakage verdict. The standard numeric `bytes` sample label is allowed by the independent decoder; string/context labels are rejected. No application pprof label calls were found in the frozen non-test backend. Goroutine WriteTo(debug=0) records symbolic stack locations, not argument values. The harness never uses the goroutineleak profiler or an HTTP heap endpoint.

The sampler itself allocates, ReadMemStats stops the world, and profile creation can allocate and cause **natural** cycles. These are perturbations shared with the matched instrumented control, not proof of identical timing to the historical image. Samples nominally run every 100ms; the analyzer rejects gaps/durations over 250ms instead of claiming missing observations. Profiles are bounded to 8MiB each, sequentially acknowledged, and taken after the original collector completes the full five-second tail.
