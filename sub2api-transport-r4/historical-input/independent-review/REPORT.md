## Findings

1. **P1: The integrated load driver does not enforce the exact-volume / near-limit-frame qualification.** `.spike-inputs/candidate/sub2api-transport-r2/overlay/sub2api-regression-lab/run.mjs:199–202` accepts downstream `bytes >= mib*MiB`, ignores upstream byte counts, and records `max_frame_bytes` without requiring the expected near-2MiB frame. Independent tests execute the actual extracted `load()` function, with its I/O dependencies replaced by deterministic in-memory fixtures. A valid control passes. Adding one downstream byte, reporting one fewer upstream byte while preserving downstream volume, or replacing the near-limit frame measurement with 5,000 bytes each still yields `functional_status: PASS`. These are three failing regression expectations, not newly observed engine faults. Require exact downstream and upstream volumes, and enforce the intended frame qualification in the real driver; retain protocol/effect/close gates. Sampled memory acceptance remains NOT RUN in these reproductions, so this finding concerns the separately reported functional gate, not an asserted aggregate physical-memory green.

2. **P2: The driver coerces numeric-array evidence.** A JSON-shaped `bytes: [8388608]` also yields functional PASS because `>=` coerces the array; its downstream aggregation becomes a string. A `{value:8388608}` object is rejected. The actual Inspector currently produces scalar numbers, so this is a driver boundary hardening gap, not proof the normal transport can manufacture such an array. Require finite numeric scalar byte/frame/text counts before comparison/aggregation. The independently tested telemetry adapter correctly rejects objects, arrays, strings and null for its numeric sample fields, without coercion.

3. **Review input mismatch / missing provenance:** the supplied candidate and hash manifest contain **transport-r2**, not a `transport-r3` directory or artifact. The r2 canonical integration patch reconstructs exactly, but the frozen-root patch references an absent `.spike-inputs/prior-code` baseline. The historical `.spike-inputs/execution.json` is also absent. Therefore approval of the specifically requested frozen r3 and replay of its root-driver patch cannot be established from this checkout. Do not relabel these files as reviewed r3. Supply the exact r3 hashes and its frozen base when integrating; the missing-history test must remain visibly unavailable rather than being replaced by invented history.
