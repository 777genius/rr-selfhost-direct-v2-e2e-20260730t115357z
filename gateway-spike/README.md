# Standalone provider gateway spike

Project **review-router-gateway-spike/poc-20260930**. Disposable repository only. Node 24 builtins, no npm dependencies. The broker owns GitHub run authorization independently of client identity. Runner receives a random run capability; Bifrost virtual-key value and upstream keys stay on the server. This is implementation plus deterministic contracts, not live provider proof.

## Operator commands

```sh
node --test gateway-spike/*.test.mjs
node gateway-spike/broker.mjs /private/broker-config.json
# Workflow invokes this from gateway-spike/ with GitHub OIDC runtime variables:
node run-client.mjs mimo codex
```

Use `broker.config.example.json` as the private broker configuration. Replace workflowSHA with the approved full commit SHA used by **main's workflow**, and each keyID with its actual Bifrost **DBKey UUID**, not a display name. Owner ID is 13103045; repo identity and workflow path are immutable in code. No broker input contains upstream provider keys. `BIFROST_ADMIN_AUTH`, if required by your admin deployment, is broker-only administration authentication, never runner environment. Create `/state` privately with persistent writable storage; ledger reserves each scope before any admin POST. Keep it across broker restarts: restarted scopes deny rather than mint replacements. Don't delete it while runs may still exist. Failed/ambiguous create also permanently consumes that scope; inspect manually instead of retrying dispatch. Restart loses capabilities and closes runner access; existing VKs expire within 15 minutes.

The public broker listens on private runner-network port 8787 at **http://broker:8787**. Its entire API is GET `/health`, POST `/grant`, POST `/openai/v1/responses`, POST `/anthropic/v1/messages`. Query strings, admin, Chat, count_tokens, arbitrary URLs and other routes are unavailable. Grant body is exactly `{ "provider": "mimo" | "openrouter", "protocol": "responses" | "messages" }`; OpenRouter Messages is unavailable. Inference model must equal the granted alias/model. All caller headers are discarded; only Messages anthropic-version/beta propagate. Bifrost receives `x-bf-vk`, never caller auth. No inference retries, fallback or error-to-success conversion. SSE bytes pass through unchanged; abrupt upstream truncation destroys the runner response. Limits: 2 MiB JSON, 32 accepted attempts (including malformed/routing-denied bodies), two in-flight requests including body reads, 120-second request deadline, TTL <= 900 seconds bounded by OIDC expiry. Revocation aborts active upstreams. Import `createBroker` and call `revoke(capability)` server-side; no public revoke/admin route. `close()` revokes all known keys. Revocation delete failures produce metadata only; local denial remains enforced and gateway TTL bounds leaked VK lifetime.

## Private Bifrost setup (operator only)

Pin OSS **v2.2.4**, source **ed8371a9779bfbc8aa689d4d77964cf8ce9308bf**, image **maximhq/bifrost@sha256:5f8215163cea192451f4b2ee5e0b583874ffe9435a5ab733e08c07aaf38ace57**. Do not substitute latest. `bifrost.template.json` is a secret-free setup candidate: empty keys deliberately prevent inference until the operator injects private upstream keys and reads resulting DBKey UUIDs. Enable mandatory governance header auth, prohibit direct keys, turn off content logging, enable database encryption at rest. Verify these fields against the pinned build before execution; documentation/source retrieval was blocked in the implementation sandbox.

Official primary references: [custom providers](https://docs.getbifrost.ai/providers/custom-providers), [virtual keys](https://docs.getbifrost.ai/features/governance/virtual-keys), [Codex](https://docs.getbifrost.ai/cli-agents/codex-cli).

MiMo native Responses uses custom_provider_config **base_provider_type openai**, Responses and stream enabled, origin `https://token-plan-sgp.xiaomimimo.com`, exact path `/v1/responses`, model **mimo-v2.6-pro**. OpenRouter also uses an **openai custom provider**, origin `https://openrouter.ai/api`, path `/v1/responses`, model **openai/gpt-4.1-mini**; do not use a provider adapter that bridges Responses to Chat. MiMo Messages uses a separate **anthropic** custom provider, candidate path `/anthropic/v1/messages` on the same region origin. Operator must confirm Messages path and supported model before canary. The template enables Anthropic chat/stream request types for the native Messages compatibility endpoint; verify stream tool_use events, no cross-protocol translation. Verify path overrides append to the supplied base URLs as intended in this pinned build.

Broker dispatches Responses to gateway `/v1/responses` and Messages to `/anthropic/v1/messages`. Native upstream path overrides belong exclusively to Bifrost. Admin create is `/api/governance/virtual-keys`, with allow_all_providers:false, a single provider_configs entry, exact key_ids and allowed_models, expires_at. Accepted create response is `{ "virtual_key": { "id": "...", "value": "..." } }`. Verify this and DELETE `/api/governance/virtual-keys/{id}` against private admin first; adjust adapter if the pinned build differs. Missing/malformed create response fails closed.

Place Bifrost exclusively on a separate private control network accessible only to broker/operator. Bifrost exposes admin and inference on the same listener: keeping the entire listener off the runner network protects admin without another proxy. Broker joins control and runner networks and exposes only its three POST routes; runner must never share Bifrost's network or resolve/reach its control address. The example uses the same fixed private Bifrost origin for admin and inference. If the operator adds an inference edge proxy, restrict it to POST `/v1/responses` and `/anthropic/v1/messages`, blocking all admin paths and preserving raw streams. Runner can reach broker only and required GitHub endpoints, never control/admin, upstream providers, host socket, host directories or credential roots. No public port needed. Operator must enforce egress isolation; this patch does not deploy networking. HTTP is only for this isolated internal network; production ingress needs TLS.

## Verification gates and limits

`TEST_CONTRACTS.md` states each observable red defect before its test. Tests sign real RSA JWTs and inject JWKS/time at verifier boundary; production never supports an auth bypass. Transport tests use actual Node HTTP upstream/admin/broker listeners, assert byte preservation, error/truncation, cancellation, routing and limits. They require loopback network permission. Record actual execution results in HANDOFF.md; a blocked test is not a pass.

Before live canary: complete pinned Bifrost schema/admin/inference authentication probes, runner isolation and secret-custody checks; independent exact-patch review; operator-approved checkout pin; then one deliberate Codex MiMo canary and one OpenRouter canary, inspect each before any remedial attempt. Claude MiMo is optional and separate. Record Actions URLs, client/image/source pins, actual event/tool evidence, measured effort and teardown. Revoke keys, stop only this project's ephemeral resources, retain normalized evidence. Live upstream pricing, region support, model/tool schema and real GitHub claims remain unproven here. Full product needs durable capability storage/reconciliation across processes, key rotation, audited workspace policy, TLS and existing OIDC integration. This PoC runs one broker process; memory/tombstones grow with scopes, so restrict the short spike's run volume. A ledger cannot safely support multiple broker writers without an external transaction store.
